Brand kit

Taru's logo, colors, type and voice, and how to use them. The colors and sizes on this page are read from shared/ui/theme.css, the file the site loads, so they always match the product.

The name

  • Write Taru, with a capital T, in sentences. The logo's wordmark is lowercase, but running text isn't.
  • Taru is the product's name, so it takes no article: "push to Taru", not "push to the Taru".
  • Don't write TARU or TaRu, and don't add a domain or a suffix to the name.

The logo

The mark is a lowercase t whose crossbar grows into a branch. The lime node at its tip is the newest commit. The wordmark is Instrument Sans SemiBold, outlined, so the logo never depends on a font.

  • Drawn on a 32-unit grid with one 4-unit stroke and round ends.
  • The node is 8.5 units across and sits on the branch's tip. On a light ground it gets a 1.5-unit ink ring, because lime alone is too faint on white.
  • Leave the node's width of clear space on every side of the mark or the logo.
  • Smallest sizes: the mark at 16px, the full logo at 20px tall.

Color

Mostly ink and paper, and one lime. Lime is new growth: the tip of the branch, the commit that just landed, and the button that makes the next one. Values are OKLCH, so equal lightness looks equal, and the neutrals carry a trace of the lime hue.

Each ratio is the contrast that matters for the role: text against the page, or the text that sits on a fill. Text needs 4.5:1 and outlines 3:1; a test in features/brand/ui fails CI if a change breaks that.

  • One lime thing per area: the button, or the commit id you're pointing at.
  • Lime is a fill with dark ink on it. It's never a large background and never text on a light page.
  • Green, teal and red only report status, and always with a word next to them.

Type

One family does the talking: Instrument Sans, set tight at large sizes. JetBrains Mono is for what a machine reads: code, commit ids, commands and labels. Both are open source (SIL Open Font License) and served from the site, not a font CDN.

Space and shape

A 4px scale, with one fluid step for the gap between sections. Corners are sharp but not hard, and surfaces separate with a hairline on light and with lightness on dark. No shadows, blur or gradients.

The signature: a lime commit id

When a page points at a change, its commit id gets the lime highlight, set in mono. On the landing page the same id shows up in an API response, in git pull and on GitHub, and the highlight is what tells you it's one change.

  • Use it for the one commit the reader should follow. Other ids stay plain.
  • Mono text on the lime fill, in both schemes. Never lime text.
  • Not for headings, links, tags or decoration.

Don't

  • Swap or change its colors.

  • Put it on lime or on a busy image.

  • Stretch, squash or rotate it.

  • Add shadows, glows or gradients.

  • taru

    Retype the wordmark in another font.

  • Drop the node. Without it the mark is just a t.

Using the tokens

Import the theme and use the role names. Components never write a raw color or size, so a change to the theme reaches every page. The reasons behind these choices are in .critly/direction.md.

CSS a card
@import "../../../shared/ui/theme.css";

.card {
  padding: var(--space-6);
  background: var(--surface);
  border: 1px solid var(--line);
  border-radius: var(--radius-card);
}

.card h3 {
  font: 600 var(--text-h3) / 1.25 var(--font-display);
}

.card p {
  color: var(--text-muted);
}
