# Win the agent review queue before the forge

The opening for a solo founder is not "a better GitHub". It is the review and merge queue that AI agents now flood. That queue sits on GitHub, it is getting worse, and the teams stuck in it already pay for help. GitHub's moat is not Git, which anyone can clone and host. The moat is the metadata, CI, identity and social graph built on top of Git, so a new forge that asks for a hard cutover will lose the way Gitorious and Google Code lost. The loudest anger at GitHub in 2025-2026 came from values-driven open-source maintainers who move but rarely pay, and from people reacting to outages. Commercial teams complain and stay, and they buy tools that sit on top of GitHub: CodeRabbit went from about $5M to $40M ARR in a year, and Cursor bought Graphite for more than its last $290M valuation. Phase 1 as planned is roughly right. One part of it is now stale: GitHub shipped native stacked PRs on every plan on October 6, 2026, so stacks are table stakes, not a wedge. Generic AI review comments are a crowded, well-funded fight. The open gap is coordination: which agent PR to look at first, how review feedback gets back to the agent, and how parallel agent branches stay mergeable, delivered through an inbox plus a CLI/MCP that agents themselves use. The first paying customer is the tech lead of a 2-20 engineer startup whose agents open more PRs than the humans can review. Popular OSS maintainers are design partners and distribution, not revenue. At $15 per active committer and about 8 seats per team, roughly 100 teams pays one founder, but only if AI costs are metered or bring-your-own-key. Since the code is cheap to write, the scarce work is a month of disciplined interviews, a concierge install on real repos, and paid pilots before anything is built in depth.

## Git stores snapshots; the forge owns everything that locks people in

The first thing to understand is how little Git does. Git is **"a content-addressable filesystem"**: file contents are stored as blobs keyed by their SHA hash, directories as trees that point at blobs, and each commit points to one full snapshot tree plus its parent commits, which makes history a tamper-evident hash chain ([Pro Git, Git Objects](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects)). Branches and tags are tiny files naming a commit hash, which is why **branching is nearly free** ([Pro Git, Git References](https://git-scm.com/book/en/v2/Git-Internals-Git-References)). Over the network, "smart" protocols negotiate which objects each side lacks and stream a packfile of only the missing ones ([Pro Git, Transfer Protocols](https://git-scm.com/book/en/v2/Git-Internals-Transfer-Protocols)). Every clone carries full history, so a central server is a social convention, not a technical requirement. Linus Torvalds built Git in 2005 after the Linux kernel lost free use of BitKeeper ([Pro Git, history](https://git-scm.com/book/en/v2/Getting-Started-A-Short-History-of-Git)).

Git has **no user accounts, access control, review, issues, CI or discovery**. A forge supplies all of that ([Pro Git, Git on the Server](https://git-scm.com/book/en/v2/Git-on-the-Server-The-Protocols)). GitHub's own price list makes the boundary plain: protected branches, required reviewers, CODEOWNERS enforcement, SAML SSO, audit logs and Actions minutes are what you pay for ([GitHub Pricing](https://github.com/pricing)). Three product consequences follow. First, a forge is mostly a database of metadata (PRs, reviews, check results) keyed to commit hashes and refs. That metadata does not travel with `git clone`, and this is the real switching cost. Second, every rebase or amend changes a commit's hash, which breaks "review this exact change" once a branch is rewritten. Gerrit's Change-Id trailer and Jujutsu's stable change IDs exist to fix this. Any review product that handles stacks well has to track the identity of a change across rewrites, not raw hashes. Third, the expensive parts of a migration are issue and review history, Actions YAML, integrations, branch rules and SSO mappings. A challenger needs importers and a way to coexist with GitHub, not a demand to cut over.

Jujutsu (jj) shows where the user model is heading. In jj, **the working copy is itself a commit** and is snapshotted automatically. There is no staging area, branch names are optional, conflicts can be stored inside commits and resolved later, and rewriting a commit **automatically rebases all its descendants**, which is exactly the chore that makes stacked changes painful in plain Git ([jj docs, Git comparison](https://docs.jj-vcs.dev/latest/git-comparison/)). Because jj stores everything in a Git backend, it works with GitHub remotes. That explains why Git UX pain alone rarely pushes anyone to switch hosts: people install jj and stay put. jj has about **32,000 GitHub stars** and repeated front-page Hacker News posts ([GitHub API](https://api.github.com/repos/jj-vcs/jj); [HN](https://news.ycombinator.com/item?id=47763759)). Its creator, Martin von Zweigbergk, joined the funded startup ERSC as CTO in September 2026, arguing that "the remote server is still Git, which has a ceiling that comes fast for products at scale" ([ERSC](https://ersc.io/blog/martin-joins-ersc)).

The daily loop the founder is building on is: branch or fork, push, open a pull request, review line by line while CI checks run, then merge by merge commit, squash or rebase ([GitHub Docs](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/about-pull-requests)). Rulesets, CODEOWNERS and the merge queue govern that loop on busy repos ([GitHub Docs, merge queue](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)). The PR is now also the interface for agents. The Copilot coding agent takes an assigned issue, works in an Actions environment, opens a draft PR and asks for review ([GitHub Changelog](https://github.blog/changelog/2025-09-25-copilot-coding-agent-is-now-generally-available/)). In July 2026 Satya Nadella said **"1 in 3 pull requests on GitHub now involves an agent"** ([Microsoft FY26 Q4 transcript](https://www.fool.com/earnings/call-transcripts/2026/08/07/microsoft-msft-q4-2026-earnings-call-transcript/)). The founder's layer also has a hard technical ceiling: a GitHub App installation gets **5,000 REST requests per hour, rising to at most 12,500** (15,000 on Enterprise Cloud) ([GitHub rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)). An inbox that polls will hit that cap on a busy org. The product has to be built on webhooks, caching and git-protocol fetches from day one.

## GitHub won on timing and taste, then compounded into 225 million defaults

GitHub co-founder Scott Chacon names **"exactly two reasons"** GitHub won: timing and taste. It launched in 2008, just as distributed version control made forking and merging cheap. Its user-centric namespacing and pull requests replaced emailing patch files, and the founders seeded it in the Ruby on Rails community. By December 2008 it hosted **about 27,000 public repos against about 1,000 on Bitbucket** ([GitButler blog](https://blog.gitbutler.com/why-github-actually-won)). Git beat Mercurial largely because of where the community and hosting went. Bitbucket eventually dropped Mercurial after **fewer than 1% of new users chose it** ([Atlassian](https://www.atlassian.com/blog/bitbucket/sunsetting-mercurial-support-in-bitbucket)). Competitors that added Git late lost. Google Code shut down in 2015 and pointed users to GitHub ([GitButler blog](https://blog.gitbutler.com/why-github-actually-won)). For a founder this is the most important history lesson: **forges win by being where a community already is, with a product its members find obviously nicer**, and they lose by arriving second to a network.

Microsoft bought GitHub in 2018 for **$7.5B in stock**, when it had 28 million developers ([Microsoft 8-K](https://www.sec.gov/Archives/edgar/data/0000789019/000119312518182975/d600091dex991.htm)). It then made private repos free in 2019 ([TechCrunch](https://techcrunch.com/2019/01/07/github-free-users-now-get-unlimited-private-repositories)) and built Actions and Copilot. Scale now reinforces the default: **180M+ developers, 630M repos and 518.7M PRs merged in the year to October 2025** ([Octoverse 2025](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/)), **225 million users** and use by over 90% of the Fortune 500 by July 2026 ([Microsoft FY26 Q4](https://www.fool.com/earnings/call-transcripts/2026/08/07/microsoft-msft-q4-2026-earnings-call-transcript/)). The moat stacks in layers. Profiles and contribution graphs work as a developer's resume. Stars, forks and trending drive discovery. Open-source dependencies and maintainers live there. Thousands of tools use "Sign in with GitHub", and every major coding agent targets GitHub's PR and issue APIs. Stack Overflow's 2025 survey puts **GitHub at 81.1% of developers against GitLab's 35.6%** ([Stack Overflow 2025](https://survey.stackoverflow.co/2025/technology/)).

The business shape matters more than the user count. Individuals and open source are the funnel. Organizations pay through Team seats at $4, Enterprise seats at $21, Copilot, Actions and Advanced Security ([GitHub Pricing](https://github.com/pricing)). The last official revenue figure is a **$2B run rate in July 2024**, when Copilot drove over 40% of revenue growth ([Siasat](https://www.siasat.com/copilot-driving-githubs-growth-annual-revenue-run-rate-at-2-billion-nadella-3071173/)). Copilot moved to usage-based billing on June 1, 2026 ([GitHub blog](https://github.blog/news-insights/company-news/github-copilot-is-moving-to-usage-based-billing/)), and Copilot revenue then grew **more than 60% quarter over quarter** ([Microsoft FY26 Q4](https://www.fool.com/earnings/call-transcripts/2026/08/07/microsoft-msft-q4-2026-earnings-call-transcript/)). GitLab, the public comparable, earned **$955.2M in FY2026 with 118% net retention**. About 10,700 customers above $5K ARR and 155 above $1M make up the business ([GitLab 10-K](https://www.sec.gov/Archives/edgar/data/1653482/000162828026018731/gtlb-20260131.htm)). The lesson for pricing is that base forge seats are cheap and the free tier is generous, so nobody beats GitHub on hosting price. The money sits in workflow, AI and compliance.

GitHub's position in 2026 is weaker than its scale suggests. In August 2025 CEO Thomas Dohmke left, GitHub was folded into Microsoft's CoreAI organization, and no replacement CEO was named ([TechCrunch](https://techcrunch.com/2025/08/11/github-ceo-to-step-down/)). A migration to Azure began in October 2025. In April 2026 GitHub's CTO admitted that "since the second half of December 2025, agentic development workflows have accelerated sharply" and that the company had to design for **30x its previous scale**, putting "availability first, then capacity, then new features" ([GitHub blog](https://github.blog/news-insights/company-news/an-update-on-github-availability/)). Commits went from **1B in all of 2025 to 1.4B per month in 2026** ([The Register](https://www.theregister.com/software/2026/06/12/github-outages-persist-as-ai-coding-drives-traffic-surge/5255125)). But GitHub still ships. Stacked PRs reached general availability on October 6, 2026 with approvals that survive rebases, merge-queue integration and a `gh stack` CLI ([GitHub Changelog](https://github.blog/changelog/2026-10-06-stacked-pull-requests-generally-available/)). The founder should assume GitHub copies any popular workflow feature within one to two years. Stacks, merge queues and rulesets were all third-party categories before GitHub absorbed them.

## The loudest complaints come from people who rarely pay

Reliability is the pain most likely to change behavior, because it stops shipping. On April 23, 2026 a merge-queue bug produced squash commits that reverted earlier merges in **658 repos and 2,092 PRs**, and GitHub "could not safely repair every repository automatically" ([GitHub blog](https://github.blog/news-insights/company-news/an-update-on-github-availability/)). This was a correctness failure, the kind enterprises fear most. A third-party tracker puts trailing three-month uptime at **98.21% for Actions and 98.49% for pull requests**, at about 23 incidents a month ([isgithubcooked.com](https://isgithubcooked.com/)). GitHub's own status page shows about 99.9% ([The Register](https://www.theregister.com/software/2026/06/12/github-outages-persist-as-ai-coding-drives-traffic-surge/5255125)). Neither number is a rigorous measurement. Mitchell Hashimoto announced on April 28, 2026 that Ghostty would leave because GitHub "is no longer a place for serious work if it just blocks you out for hours per day" ([mitchellh.com](https://mitchellh.com/writing/ghostty-leaving-github)). It was the biggest story in this whole topic, at **3,521 HN points** ([HN](https://news.ycombinator.com/item?id=47939579)). Yet as of October 12, 2026, Ghostty is still developed day to day on GitHub, still accepting new PRs and merging commits ([GitHub API](https://api.github.com/repos/ghostty-org/ghostty)). If a wealthy, motivated, publicly committed maintainer has not moved after five and a half months, **announcing an exit is cheap and completing one is expensive**.

GitHub Actions draws the most sustained anger: a push-and-wait debug loop, YAML with its own expression language bolted on, a log viewer that "has crashed my browser... repeatedly", silent cache misses and an insecure marketplace ([Ian Duncan](https://www.iankduncan.com/engineering/2026-02-05-github-actions-killing-your-team/)). The tj-actions supply-chain attack rewrote version tags in an action used by about 23,000 repos ([The Hacker News](https://thehackernews.com/2025/03/github-supply-chain-breach-coinbase.html)). In December 2025 GitHub announced a $0.002/minute fee on self-hosted runners and postponed it within about 48 hours after an **802-point HN revolt** ([The Register](https://www.theregister.com/2025/12/17/github_charge_dev_own_hardware/); [HN](https://news.ycombinator.com/item?id=46291156)). This pain is real, but it is already monetized by runner vendors such as Blacksmith, Depot and Buildkite. A new forge does not fix CI by existing, which is why Cursor Origin and GitCafe both hand CI to Buildkite or Depot.

AI produces two opposite complaints. Anti-AI maintainers object to Copilot being pushed at them. In March 2026 Copilot injected promotional "tips" into PRs, including human-written ones, which GitHub reversed the same day ([The Register](https://www.theregister.com/2026/03/30/github_copilot_ads_pull_requests/)). The same month GitHub announced default-on training on Copilot interaction data for Free, Pro and Pro+ users ([heise](https://heise.de/-11226787)). They also object to the flood of low-effort AI PRs. curl ended its bug bounty in January 2026 ([The Register](https://www.theregister.com/2026/01/21/curl_ends_bug_bounty/)). GitHub opened a discussion about a PR "kill switch", in which one maintainer estimated **"1 out of 10 PRs created with AI is legitimate"** and another said "reviewers can no longer assume authors understand or wrote the code they submit" ([The Register](https://www.theregister.com/2026/02/03/github_kill_switch_pull_requests_ai/)). Meanwhile AI-heavy users object to hosts that restrict them. Codeberg's members voted 358 to 144 to ban projects that mostly consist of AI-written code ([It's FOSS](https://itsfoss.com/news/codeberg-bans-ai-contributions/)). That turned Theo from donor to critic within weeks ([YouTube](https://www.youtube.com/watch?v=Y8cY1DEURtE)) and produced a 565-point "I regret migrating to Codeberg" post ([HN](https://news.ycombinator.com/item?id=49021856)).

Theo's May 2026 thread is the clearest statement of the "agent-native source control" thesis. He opened with "GitHub is dying and git is not the right primitive" and asked someone else to build the fix ([X](https://x.com/theo/status/2059428277786468407)). His asks are partial privacy inside public repos, including embargoed security fixes and private sub-packages ([X](https://x.com/theo/status/2059428863135174829)); no commit or branch bookkeeping ([X](https://x.com/theo/status/2059429257038987375)); cheap copy-on-write workspaces for parallel agents ([X](https://x.com/theo/status/2059429524581085647)); and API access to source without a full filesystem. Three caveats apply. Theo has CI vendors as sponsors, so treat his views as a signal from the agent-heavy TypeScript crowd, not neutral evidence. Some of his asks are partly solved already: Git can check out the same branch in two worktrees with `--force` ([git-worktree docs](https://git-scm.com/docs/git-worktree)), and GitHub supports private vulnerability reporting and temporary private forks ([GitHub Docs](https://docs.github.com/en/code-security/tutorials/fix-reported-vulnerabilities)). And jj addresses most of the bookkeeping complaint locally.

Who actually moves? Zig moved to Codeberg in November 2025, citing Actions neglect and its no-AI policy. It gave up GitHub Sponsors, **its largest single income source at over $170K in 2024** ([ziglang.org](https://ziglang.org/news/migrating-from-github-to-codeberg/); [DevClass](https://devclass.com/2025/11/27/zig-project-ditches-github-for-codeberg-but-move-could-be-costly/)). Gentoo is mirroring to Codeberg ([gentoo.org](https://www.gentoo.org/news/2026/02/16/codeberg.html)) and Gleam moved to Tangled ([Tangled](https://tangled.org/gleam.run/gleam)). Some projects move back: Endurain migrated from Codeberg to GitHub on October 8, 2026 ([GitHub PR](https://github.com/endurain-project/endurain/pull/800)). No large commercial company publicly left GitHub in 2025-2026 in the sources reviewed. The pattern is consistent. **Values-driven open-source projects pay with migration effort, not money. Commercial teams pay money, but they stay on GitHub and add tools on top.** As one essay puts it, "there are plenty of places to host a Git repository, but remarkably few places to host an open-source community" ([lalitm.com](https://lalitm.com/post/github-alternatives/)).

|---|---|---|---|
| Outages and merge correctness | Teams that ship many times a day; big OSS | Ghostty's announcement; Cursor Origin launched on an outage day ([InfoQ](https://infoq.com/news/2026/08/cursor-origin-alternative-github)) | Severe, but a layer on GitHub inherits it. Strongest argument for Phase 2 |
| Agent-scale review overload | Agent-heavy startups (budget); big OSS (no budget) | CodeRabbit's growth; Entire's $60M seed on this thesis ([entire.io](https://entire.io/blog/hello-entire-world/)) | **The paying wedge for Phase 1** |

## Review, not writing code, is where the money moved

The bottleneck has shifted downstream. Faros AI telemetry on 10,000+ developers found that high-AI-adoption teams **merged 98% more PRs, but review time rose 91%, PR size rose 154%**, and company-level delivery metrics did not improve ([Augment Code summary of Faros](https://www.augmentcode.com/guides/ai-productivity-paradox-engineering-delivery); this is a secondary summary, since the primary report was not retrieved). DORA's 2025 report reached the same conclusion: AI "is exposing the downstream bottlenecks in testing, code review, and quality assurance" ([DevOps.com](https://devops.com/dora-2025-faster-but-are-we-any-better/)). GitHub's own explanation of its outages, agent traffic forcing a 30x capacity redesign, says the same from the infrastructure side.

Teams demonstrably pay to clear that bottleneck. **CodeRabbit reached a reported $40M ARR in April 2026, up from about $5M a year earlier, with 17,000+ customers**, and raised $143M at a $1.5B valuation ([arr.club](https://www.arr.club/coderabbit/coderabbit-revenue-up-5x-yoy-with-143m-series-c-at-1-5b-valuation); the 2026 figures come from aggregators). It charges **$24-48 per PR author per month** ([Sacra](https://sacra.com/c/coderabbit/)). Graphite charges $20-40 per user ([Graphite pricing](https://graphite.com/pricing)). It served 500+ companies including Shopify and Figma, and Cursor bought it in December 2025 at a price reported as "way over" its last $290M valuation ([Fortune](https://fortune.com/2025/12/19/cursor-ai-coding-startup-graphite-competition-heats-up/)). Greptile charges about $30 a seat and sells self-hosted deployments on annual contracts ([Sacra](https://sacra.com/c/greptile)). So a 10-engineer team paying GitHub $40 a month for Team seats can easily pay several hundred more for review tooling. **The review layer commands a bigger budget than the forge itself.** That is the strongest economic argument for starting with Phase 1.

The competitive field is also the strongest argument for narrowing Phase 1. Well-funded players cover generic AI review (CodeRabbit, Greptile, Copilot review bundled into Copilot seats), stacks plus review (Graphite inside Cursor, which SpaceX acquired in August 2026 ([Mobile World Live](https://www.mobileworldlive.com/ai-cloud/spacex-completes-60b-cursor-acquisition/))), agent-era hosting (Cursor Origin with two-way GitHub sync ([Cursor changelog](https://cursor.com/changelog/origin-code-hosting)); Entire's $60M seed and its agent git network ([TechCrunch](https://techcrunch.com/2026/02/10/former-github-ceo-raises-record-60m-dev-tool-seed-round-at-300m-valuation/embed/)); ERSC; GitButler's $17M Series A ([GitButler](https://blog.gitbutler.com/series-a))) and raw git storage for agents (Pierre's Code Storage, Cloudflare Artifacts) ([code.storage](https://code.storage/); [Cloudflare](https://www.cloudflare.com/products/artifacts/)). GitCafe already pitches MCP access and native stacks ([GitCafe docs](https://git.cafe/docs/agent-workflows)). Pierre's history is a warning. It launched through YC as a polished code review app, then paused signups to sell storage infrastructure instead ([HN](https://news.ycombinator.com/item?id=46961760)).

A solo founder cannot outspend any of these. The defensible ground is where they are structurally weak. The first area is **coordination across many agent-authored PRs**: ranking the queue, grouping related agent branches, telling agent-dumped PRs from human-checked ones, and closing the loop so review feedback goes straight back to the agent through a CLI or MCP server. Today a human relays it. The second is **open source and self-hostability as trust**: the funded players are closed or cloud-only, while Phacility's shutdown showed that an open license is what let users continue through the Phorge fork ([Phacility](https://admin.phacility.com/phame/post/view/11/); [Wikipedia](https://en.wikipedia.org/wiki/Phabricator)). The third is **forge neutrality**: a layer that also works on Forgejo, Gitea or GitLab cannot be killed by a single GitHub changelog entry. The interviews have a clear test for whether the wedge is real. If tech leads describe their pain as "too many low-quality AI comments", that market belongs to CodeRabbit. If they describe coordination, meaning what to look at first, agents ignoring feedback, and parallel branches conflicting, the gap is open.

The cheap-software premise cuts both ways. A 2026 essay put it bluntly: software being hard to build "stopped being true about six months ago", and the new moat is "everything around the product that does not compress with better code generation" ([stroupaloop.com](https://stroupaloop.com/blog/2026/04/12/when-code-gets-cheap-scarcity-moves/)). Whatever the founder builds in a weekend, a funded competitor or GitHub can build in a sprint. What compounds instead is distribution (an audience, launch channels, community), trust (uptime history, an open license, transparent finances, export in both directions), taste in one narrow workflow, and data gravity once a team's review history lives in the product. Tailwind Labs adds an AI-era warning about distribution: revenue fell about 80% even with roughly 75M monthly downloads, because AI assistants write Tailwind code without sending users to the docs that sold the paid product ([DevClass](https://www.devclass.com/2026/01/08/tailwind-labs-lays-off-75-percent-of-its-engineers-thanks-to-brutal-impact-of-ai/)). A docs or SEO funnel is fragile. Direct channels are sturdier: HN launches, posts on X, agent-tool directories and MCP registries.

## The first customer is a tech lead whose agents out-produce them

The ideal first customer sits where three things overlap: the person who feels the pain, the person who holds the card, and someone who can install a GitHub App in five minutes. That overlap is tightest in **AI-heavy startups of 2-20 engineers**. In those teams, Claude Code, Codex, Cursor or Copilot agents open a large share of PRs, the team is on GitHub Team, it has tried or pays for CodeRabbit, Graphite or Greptile, and one tech lead or CTO spends more than an hour a day reviewing. The qualifiers for this ICP-A are: a meaningful share of merged PRs written by agents, or engineers running several agents in parallel; a self-reported backlog ("PRs sitting for days"); current or past spend on an AI review tool, which proves both budget and an unmet need; the buyer is the reviewer; and the code is hosted on GitHub. The best evidence of pain is a homemade workaround: a script, GitHub Action or MCP server built to manage the queue.

The second segment, ICP-B, is **maintainers of active open-source repos who were hit by AI PRs in 2026**. That means 1,000+ stars and steady external PRs, plus a public complaint, a new AI contribution policy or newly restricted PR settings. Their pain is the most acute and the most visible: Ghostty banned AI-generated code and tldraw auto-closes external PRs ([OpenSourceForU](https://www.opensourceforu.com/2026/02/github-weighs-pull-request-kill-switch-as-ai-slop-floods-open-source/)). But they have almost no money. Treat them the way CodeRabbit does, with a free tier for open source (it reports 150,000 OSS projects ([arr.club](https://www.arr.club/coderabbit/coderabbit-revenue-up-5x-yoy-with-143m-series-c-at-1-5b-valuation))). Their endorsements spread to the startups that do pay, and an open-source product fits their values. What they would value: triage that separates human-checked from agent-dumped PRs, contributor reputation, bulk close with templated replies, and an AI-attribution signal.

The anti-ICP for year one is just as important. Enterprises need SSO, SOC 2, audit logs and procurement cycles a solo founder cannot staff. Students have no review pain and no budget. Small hobby maintainers are advocates, not payers. **EU public-sector sovereignty buyers** are real and growing: the Dutch government chose Forgejo for code.overheid.nl and rejected GitHub as proprietary and GitLab for its open-core model ([It's FOSS](https://itsfoss.com/news/netherlands-forgejo-migration/)), and Germany's openCode.de has passed 5,000 users and 1,900 repos ([cosinex](https://blog.cosinex.de/2026/04/16/zendis-strategische-neuausrichtung-open-source/)). But these buyers procure through tenders, and the Dutch criterion of **"no enterprise tier, proprietary upsell, or vendor lock-in"** would disqualify a standard open-core business. They belong to Phase 2, approached through integrators or by contributing to or building on Forgejo rather than competing with it.

Several design principles follow from this customer picture and from the history above. Deliver single-player value before any network value. Google Code and Gitorious lost by competing as a destination after the network had formed elsewhere ([Engadget](https://www.engadget.com/2015-03-13-google-code-closing.html); [GitLab blog](https://about.gitlab.com/blog/gitlab-gitorious-free-software/)). Coexist rather than replace: every serious 2026 entrant, Cursor Origin, Entire and Tangled, mirrors or syncs with GitHub. Build for agent-scale traffic and a GitHub rate ceiling, which means webhooks, not polling. Track the identity of a change across rebases so stacks and re-reviews behave. Make agents first-class users of the product: an agent should be able to read its review feedback, push a fix and restack without a human relaying anything. Make AI provenance visible, since maintainers ask for disclosure and attribution. Promise export in both directions so the product is safe to adopt. And watch the noise in provenance signals: VS Code began auto-adding Copilot as a commit co-author in April 2026 ([HN](https://news.ycombinator.com/item?id=47958353)), so co-author trailers alone over-count real agent use.

## Customer-discovery plan: 35 interviews, five commitments, hard kill lines

The method is the Mom Test: talk about the customer's life rather than the idea, ask about specific past events rather than opinions about the future, and listen more than you talk ([mtlynch.io](https://mtlynch.io/book-reports/the-mom-test/)). Every conversation should end in a commitment of time, reputation or money, because "the more they're giving up, the more seriously you can take what they're saying" ([Unusual Ventures](https://www.unusual.vc/rob-fitzpatricks-mom-test/)). Linear is the model for pacing. Its founders spent more than a year interviewing peers before quitting their jobs, then ran a waitlist of about 10,000 behind a qualifying survey ("Why do you want to use it and what are your current problems?"), hand-picked **about 10 users a week**, and "with each 10-person cohort... basically made a new version of the product" ([First Round Review](https://review.firstround.com/linears-path-to-product-market-fit.md)). Supabase shows the power of a sharp label: as "the open-source Firebase alternative" it went **from 8 to 800 hosted databases in three days** after an HN post ([Contrary Research](https://research.contrary.com/company/supabase)). "The open-source review inbox for agent-written PRs" has the same shape.

### Who to talk to and where to find them

Target **about 35 interviews over four weeks, about 20 from ICP-A and 12 from ICP-B, plus 3-5 exploratory Phase 2 calls**. Stop a segment early when five interviews in a row reveal no new pain pattern. These numbers are judgment heuristics, not a published benchmark. For ICP-A, the most precise list is public startup repos whose commit history carries agent co-author trailers such as "Co-Authored-By: Claude". Discount Copilot trailers because of the VS Code default. Next come people on X posting screenshots of many parallel Claude Code or Codex sessions or complaining about agent PR volume. Then HN commenters on the Graphite-Cursor, CodeRabbit-funding and "AI productivity paradox" threads, whose profiles often name a company. Then Reddit threads in r/ClaudeAI, r/cursor, r/ChatGPTCoding and r/ExperiencedDevs. Then power users filing issues on popular agent tools (Claude Code, Aider, OpenHands, Cline). Finally, warm intros from founder friends in recent accelerator batches. For ICP-B, start with the maintainers who publicly posted about AI PRs (Ghostty, tldraw, curl, Godot, RPCS3, GoCD), then work outward through the GitHub kill-switch discussion, CNCF and OpenSSF maintainer channels, and Mastodon and Bluesky FOSS circles. For Phase 2, use the Forgejo and Codeberg Matrix rooms, the openCode.de community and the code.overheid.nl pilot's issue tracker. The activity levels of these communities in October 2026 were not verified.

The outreach should ask about their workflow, never pitch a demo. Something like: *"I'm researching how teams that use Claude Code or Codex heavily handle PR review. Saw your post about X. Could I ask you five questions in 20 minutes? Not selling anything."* Offer something in return: the anonymized findings, or a small free script that labels agent-authored PRs. Publish a short write-up of the Faros, DORA and Octoverse numbers first. It shows you understand the problem, works as an icebreaker, and starts the founder's own distribution channel.

### Interview script for ICP-A: agent-heavy startup tech lead

| # | Ask | Listen for |
|---|---|---|
| 1 | Walk me through the last PR you merged yesterday. Who or what wrote it, and how did it get to merged? | Agent share; where time went |
| 2 | Last week, roughly how many PRs did agents open, and how many did humans? How do you know? | Volume; whether they track it at all |
| 3 | Tell me about the last time a PR waited for review longer than it should have. What did it cost? | A concrete story with a cost |
| 4 | How did you decide which PR to look at first this morning? Show me your screen. | Whether a triage problem exists (inbox wedge) |
| 5 | When did you last close an agent PR without merging? Why? | Slop rate; wasted review time |
| 6 | Which review tools have you tried in the last 12 months? Which do you still pay for, what does it cost, and why did you drop the others? | Budget proof; the gap competitors leave |
| 7 | Tell me about the last time two agents' branches conflicted, or a big agent PR had to be split. What did you do? | Stacking and parallel-branch pain |
| 8 | When an agent gets review feedback, what happens next? Who relays it, and how long does it take? | **The agent-loop wedge (CLI/MCP)** |
| 9 | Have you built scripts, bots, Actions or MCP servers to manage any of this? Can you show me? | Homemade workaround, the strongest signal |
| 10 | Who else spends time on this, and roughly how many hours last week? | Size of the pain in hours |
| 11 | The last time you bought a dev tool for the team, who approved it, what did it cost, and how long from trial to paid? | Buying process and price anchor |
| 12 | Who else is dealing with this that I should talk to? | Reputation commitment |

### Interview script for ICP-B: maintainer of an active OSS project

| # | Ask | Listen for |
|---|---|---|
| 1 | Walk me through how you handled the last batch of incoming PRs on your repo. | Triage workflow today |
| 2 | Last month, how many external PRs came in, and how many were clearly AI-generated without review by the submitter? How did you tell? | Volume; detection heuristics to build |
| 3 | Tell me about the most recent AI PR that cost you real time. | Concrete cost |
| 4 | Which policies or settings did you change this year, and what triggered each? | Willingness to adopt tooling |
| 5 | Which bots or tools run on the repo today, and what have you turned off? Why? | Tolerance for bots; competitor gaps |
| 6 | Have you lost a good human contributor's PR in the noise? | Need for reputation and attribution signals |
| 7 | Who helps triage, and how many hours did it take last week? | Pain in hours |
| 8 | Does the project have money (sponsors, foundation, company)? Has it ever paid for tooling, and who approved it? | Whether any budget exists |
| 9 | Have you considered moving off GitHub? What happened when you looked into it? | Phase 2 signal and switching costs |
| 10 | Which other maintainers are dealing with this? Would you introduce me? | Reputation commitment |

Never ask "Would you use...?", "Would you pay...?" or "Is this a good idea?". Pitch only at the end, if at all, and then ask for a concrete next step. For the 3-5 Phase 2 calls, ask what they host on today, what their last procurement of developer infrastructure looked like, and whether open core would disqualify a vendor.

### What counts as demand, from weakest to strongest

Compliments, "send it to me when it's ready", unexplained feature requests and "I'd pay $X" count as zero. Moderate signals are a specific recent story with numbers told unprompted, an existing homemade workaround, or paying for a competitor while naming a specific gap. Strong signals are commitments: a second call or screen-share booked before hanging up (time); an intro to a co-founder, teammate or another maintainer (reputation); installing the prototype on a **real private repo and still using it two weeks later** (time plus risk); and a paid pilot or pre-payment, even $50-200 a month (money). For maintainers, a public endorsement or adoption on a well-known repo counts as reputation. Because building is cheap, start a concierge prototype from about interview 10: install a rough triage inbox on the interviewee's real repo for two weeks. Keep that work separate from the learning questions so the demo doesn't contaminate them.

### Timeline and gates

| Week | Activity | Gate to pass |
|---|---|---|
| 0 | Publish the bottleneck write-up; build the outreach list from co-author trailers, HN, X and maintainer posts | 60+ named prospects |
| 1-2 | 15-18 interviews; affinity-map the pains after each batch of five | A repeated pain pattern with numbers attached |
| 2-4 | 15-18 more interviews; concierge prototype on real repos from about interview 10 | 5+ teams install on real repos |
| 5-8 | Two-week concierge pilots; ask for paid pilots at $50-200/month | **5+ teams using it weekly; 2-3 paid pilots; 3-5 maintainer design partners** |
| 8 | Decide: go deep on Phase 1, change the wedge, or stop | See kill criteria |

### Kill criteria

Stop or pivot if any of these holds at the week-8 decision point. The first three come from the research notes; the last three are proposed thresholds, not sourced figures. (1) After 15+ ICP-A interviews, **fewer than about a third rank review or merge as a top-three pain**. (2) No interviewee has built a homemade workaround. (3) Most are satisfied with CodeRabbit, Graphite or GitHub's native stacks and name no specific gap. (4) Pain clusters on "low-quality AI comments" rather than coordination. That is CodeRabbit's market, so pivot away from review comments. (5) Fewer than three of five concierge installs are still in weekly use after two weeks. (6) **Zero paid pilots after 30+ interviews and 5+ installs.** Treat Phase 2 as unvalidated until several paying Phase 1 customers ask to self-host or leave GitHub and a sovereignty buyer has said what it would procure.

## Profitability plan: about 100 teams at $15 a seat pays one founder

The model with the best small-team record is **hosted SaaS on an open-source codebase**. Plausible switched to AGPL, kept "all of the code powering our SaaS" public, and reached **$1M ARR with four people in 2022** on content, HN and word of mouth with no paid ads ([Plausible blog](https://plausible.io/blog/open-source-saas)). sourcehut shows the smaller, minimalist version: **$132K revenue in 2022, 11% of registered users paying, profitable** ([sourcehut 2022 report](https://sourcehut.org/blog/2023-03-27-2022-financial-report/)). Gitea's company sells an enterprise edition at $9.50-19 per user on top of an MIT core ([Gitea pricing](https://about.gitea.com/pricing)). Sentry's FSL allows self-hosting but bars competing commercial offerings, and converts to Apache or MIT after two years ([Sentry](https://open.sentry.io/licensing/)). The failures set the guardrails. Gitorious ran free public hosting funded by a shrinking on-premises line until it "was no longer sustainable" ([The Next Web](https://thenextweb.com/news/gitlab-acquires-rival-gitorious-will-shut-june-1)). SourceForge wrapped installers in adware and lost Wine and Notepad++ ([Help Net Security](https://www.helpnetsecurity.com/2016/06/13/sourceforge-trust/)). Charge paying customers directly for what costs money, keep free hosting small, and never monetize through ads or bundling.

### Pricing

| Tier | Price | Who | Why this number |
|---|---|---|---|
| Open source and personal | Free for public repos and personal accounts | ICP-B, solo developers | Distribution and reputation, as with CodeRabbit's free OSS tier |
| Paid pilot | $50-200 per team per month, flat | First 2-10 ICP-A teams | Turns interviews into money; tests willingness to pay early |
| Team | **$15 per active human committer per month**; bring your own model key, or hosted AI with an included allowance plus metered overage | ICP-A | Below CodeRabbit ($24-48), Greptile ($30) and Graphite ($20-40), and complements GitHub's $4 Team seat rather than replacing it |
| Self-hosted (Phase 1.5/2) | $10-30 per seat, billed annually, with SSO, audit log and support | Regulated or self-hosting teams | Matches the Gitea Enterprise band; highest margin per customer |

Bill humans, not agents. Agents are the volume, and charging per agent identity would punish the customer's core behavior. Recover agent-driven cost through metered AI runs instead. Do not charge for stacks, since GitHub gives them away on every plan. Bring-your-own-key is the main margin protection, and it fits the ICP, who already pay for Claude, Codex or Cursor. Market prices show where hosted AI review should sit: Greptile charges $1 per review beyond the included 50 ([Costbench](https://www.costbench.com/changelog/greptile-price-decrease-2026-05/)), and GitLab sells AI as $1 credits ([GitLab pricing](https://about.gitlab.com/pricing/)).

### Unit economics per team

AI is the cost that can wipe out the margin. Kilo measured a single PR review at **$0.73-1.34 with Claude Opus 4.6 and $0.05-0.07 with Kimi K2.5** ([Kilo blog](https://blog.kilo.ai/p/we-analyzed-how-much-kilo-code-reviewer)). At October 2026 list prices ([Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing)), the same token counts (about 620K input tokens) work out to roughly $2.60 per PR on Opus 5.5 uncached, $0.36 on Sonnet 5.5 with heavy caching, and $0.33 on Haiku 5.5. These are calculations, and triage probably needs far less context than a full review, which is an untested assumption. At 10 developers and 20 PRs each per month, AI review alone costs $70-520 against $150 of seat revenue. **Unlimited frontier-model review loses money.** Storage and git operations are small: about $2.50 a month for 5 GB on Cloudflare Artifacts, up to about $18 if kept hot on Code Storage ([Cloudflare](https://www.cloudflare.com/products/artifacts/); [code.storage](https://code.storage/)). Payment processing took about 6.5% of sourcehut's revenue ([sourcehut](https://sourcehut.org/blog/2023-03-27-2022-financial-report/)). For comparison, GitLab runs at **84-86% gross margin** ([BusinessWire](https://secure.businesswire.com/news/home/20260901768402/en/GitLab-Reports-Second-Quarter-Fiscal-Year-2027-Financial-Results)).

| Line (team of 8, monthly) | Bring your own key | Hosted AI, 80 included runs | Basis |
|---|---|---|---|
| Revenue | $120 | $120 | 8 × $15 |
| Payment fees | −$7.80 | −$7.80 | 6.5%, sourcehut's realized rate |
| Infrastructure (webhooks, database, cache, git fetches) | −$5 | −$18 | Assumption; the upper bound is Code Storage with 5 GB hot |
| AI triage | $0 | −$26 | 80 runs × ~$0.33 (Haiku-class at full review context) |
| **Gross profit** | **~$107 (89%)** | **~$68 (57%)** | Overage beyond 80 runs billed at ~$0.50-1 |

### Path to break-even

The founder's personal cost of living is unknown and is an input to fill in. The table assumes $500 a month of fixed costs (monitoring, domains, email, the founder's own agent subscriptions) and a blended gross profit of $68-107 per team. All figures are calculations, not forecasts.

| Monthly take-home target | Teams needed (at $107 to $68 gross profit per team) | ARR at $120 per team |
|---|---|---|
| $3,000 | 33-52 | $48K-75K |
| $6,000 | 61-96 | $88K-138K |
| $10,000 | 99-155 | $143K-223K |

The anchors from the research notes are the same: 10 teams is about $14.4K ARR, side income; **100 teams is about $144K ARR, one founder's living and roughly sourcehut's 2022 scale**; 1,000 teams is about $1.44M ARR, a Plausible-sized company of 4-8 people. Conversion anchors are thin. sourcehut converted 11% of registered users to paid, and about 10% of Linear's waitlist became users in year one. If roughly one in ten installing teams converts, 100 paying teams means about 1,000 installs. That is the distribution job the founder must plan for. As targets rather than predictions: 2-3 paid pilots by week 8, 10-20 paying teams (about $1.2K-2.4K MRR) by month 6, and 50-100 by month 12-18. If month 6 shows fewer than 10 paying teams despite healthy installs, the price, the wedge or the ICP is wrong. Do not try to fix that with features.

Phase 2 has different economics. A forge competes with GitHub's $4 Team seat and with free Forgejo and Gitea, so it earns money from private hosting at about $8-20 per seat, CI passed through with an allowance and overage (Bitbucket resells 1,000 build minutes for $10 ([Bitbucket](https://www.atlassian.com/software/bitbucket/pricing))), and annual self-hosted licenses. Raw git storage is now a metered commodity, so the founder does not need to run git servers at scale, and neither does anyone else. Choose the license by segment. **AGPL** keeps the trust of the FOSS crowd and fits sovereignty buyers who reject upsells. **FSL** protects against cloud resellers but reads as "not really open". Funding is optional. Bootstrapping fits a $150K-1.5M ARR target, as Plausible, sourcehut and Laravel's first 13 years show ([Fortune](https://www.fortune.com/2024/09/05/laravel-raises-57-million-series-a-from-accel)). Raise only to race funded players on agent-scale infrastructure. Dev-tool investors in 2026 reportedly diligence "paid-team conversion, not GitHub stars" ([Causo](https://hub.causo.ai/guides/raising-seed-devtools-startup-2026); secondary source).

## Questions only customers can answer

| Open question | Why it decides the business | How to answer it |
|---|---|---|
| Is the review pain about coordination (triage, feedback loop, conflicts) or about comment quality? | Coordination is open; comment quality belongs to CodeRabbit | ICP-A questions 4, 7 and 8; count which stories recur |
| What share of 2-20 person startups use agents heavily enough to qualify? | Sets the size of the market for ICP-A | Co-author trailer search plus interview question 2 |
| Who relays review feedback to agents today, and how long does it take? | Tests whether the agent-native CLI/MCP is a must-have or a toy | ICP-A question 8; watch the screen share |
| What do teams pay for review tools now, and what made them churn? | Validates the $15 price and the gap left by incumbents | ICP-A questions 6 and 11 |
| Will teams bring their own model keys, or insist on hosted AI? | Decides gross margin (89% vs 57%) | Offer both in pilots; watch which they pick |
| Does open source change the buying decision for startups, or only for maintainers? | Decides the license, and whether AGPL helps or just reassures | Ask what gave them pause in their last vendor security review |
| Will maintainers adopt a triage bot publicly, and does their endorsement reach paying startups? | Tests the free-tier-as-distribution theory | Track installs referred by maintainer design partners |
| How much of the pain survives GitHub's native stacks and Copilot review over the next six months? | Measures platform risk directly | Re-interview pilot teams at month 3 and month 6 |
| Do paying Phase 1 customers want to leave GitHub, or just want GitHub to work? | The only legitimate trigger for Phase 2 | Interview question on switching; requests for self-hosting |
| What would a sovereignty buyer procure, and is open core disqualifying? | Defines whether Phase 2 is a forge, a Forgejo add-on, or support | 3-5 exploratory calls with Forgejo, openCode and SSC-ICT contacts |

## Conclusion

The research reverses the founder's natural order of operations. Phase 2, the forge, is the emotionally compelling part, since GitHub's outages, the Codeberg reversal and the Microsoft trust deficit all point to an empty "reliable, neutral, professionally run" slot. But the people demanding it most are the least likely to pay, and no hosted alternative escapes GitHub's social and CI gravity without a coexistence strategy. Phase 1 is less romantic and far more fundable from revenue. The review queue is where agent adoption creates a new, daily, budgeted pain, and a layer can be installed and cancelled in minutes. The founder should stop counting stacks as a differentiator: GitHub turned stacks into a commodity the same week this research was done. The defensible core is the loop between human reviewers and the agents that write the code. Open source and forge neutrality are trust assets that funded, closed competitors cannot copy cheaply.

AI coding agents make the founder's own engineering nearly free, and they do the same for every competitor. So the real deliverable of the next two months is not software but evidence: a few dozen past-tense stories, a handful of real repos still using a concierge prototype after two weeks, and the first invoices, however small. If those appear, a $150K business within reach of one person is realistic and a larger one is possible. If they do not, the kill criteria above will have saved a year of building into a market that GitHub, CodeRabbit and Cursor already hold.
